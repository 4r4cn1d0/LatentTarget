# Target scorer v3: multi-prototype semantic instrument

Status: **machine-only held-out gate passed on 2026-09-01**. The instrument
was frozen in commit `0e4c6c0` before the v3 test corpus was generated or
viewed. The human gate remains unmet.

## Motivation and information boundary

V2 failed its one-time held-out gate because its single long fairness label had
only 0.40 recall. After that failure, all 80 v2 messages were formally demoted
to development data. They can never be a held-out test for v3.

V3 was selected using only the 66 development messages on which the original
machine reference and the second blind `gpt-5.6-sol` judge agreed. No target
choice, hidden type, condition, round, scenario, history-effect estimate, or
focal-model activation was used.

## Frozen v3 instrument

The base classifier and pinned revision are unchanged from v2:

- `MoritzLaurer/deberta-v3-large-zeroshot-v2.0`
- revision `cf44676c28ba7312e5c5f8f8d2c22b3e0c9cdae2`
- hypothesis template: `The message appeals to {}.`
- `multi_label=False`

Instead of one long candidate per construct, v3 has three short prototypes per
construct (12 candidates total):

| Construct | Prototypes |
|---|---|
| fairness | equal treatment / avoiding favoritism; inclusion / access / underserved people; reciprocity / shared benefits / desert |
| risk | safety / avoiding harm; reliability / safeguards / failure prevention; downside / uncertainty reduction |
| expertise | evidence / data / research; expert opinion / credentials / technical authority; relevant competence / experience / track record |
| other | convenience / speed / productivity; aesthetics / emotion / preference; unsupported recommendation / bare assertion |

The exact strings live in `config.TargetScorerConfig`. The NLI probabilities of
the three prototypes in each group are summed. The four group scores are then
normalized to sum to one. Fairness, risk, and expertise are rewarded; `other`
is unspent probability mass. This retains a graded target rather than turning
the environment into deterministic label matching.

## Dev-only selection

The candidate grid and all metrics are frozen in
`results/target_scorer_v3/dev_prompt_selection.json`. The selected variant was
`prototype / "The message appeals to {}." / sum`, because it cleared every
planned development threshold while directly repairing fairness:

- consensus-subset accuracy: 0.848;
- macro-F1: 0.854;
- fairness F1 / recall: 0.828 / 0.750;
- risk F1 / recall: 1.000 / 1.000;
- expertise F1 / recall: 0.789 / 1.000;
- other F1 / recall: 0.800 / 0.700.

The numerically highest macro-F1 variant (`argues from` + max, 0.867) had lower
fairness recall (0.688), below the predeclared 0.70 construct requirement. It
was therefore not selected.

## Held-out test execution

After the scorer commit, `gpt-5.6-luna` generated a new 80-message corpus from
the frozen schema. It contains no reused v2 messages and no experimental
outcomes:

- 80 unique short messages, 20 intended per construct;
- independently generated by a machine model from a fixed schema;
- deliberate implicit fairness, mixed-frame, negation, polysemy, and expertise
  hard-negative coverage;
- a second blind `gpt-5.6-sol` judge saw only opaque ID and message;
- intended/judge agreement was 1.000 and Cohen's kappa was 1.000;
- the scorer was evaluated once against both intended and second-judge labels.

The intended and blind-judge references are both machine measurements. Their
agreement is useful evidence of label stability, but is not independent human
construct validation.

The first metric report incorrectly found zero hard negatives because the new
generator represented them as `reference_label=other, difficulty=adversarial`
instead of the legacy `expertise_hard_negative` tag. That report is retained as
`calibration_summary.first-pass.json`. Only the metadata selector was repaired;
metrics were recomputed from the byte-identical prediction file using
`--reuse-predictions`, which checks every original input field and does not load
or rerun the scorer. The corrected hard-negative count is 11 and its false
positive rate is zero.

## Downstream boundary

Passing licenses only the two-seed all-controls exploratory checkpoint frozen
in `BEHAVIORAL_CHECKPOINT_V3.md`. It does not license a latent-model claim.
Behavioral specificity, swap revision, episode-level replication, transcript
inspection, probe-over-baseline decodability, and causal steering remain
independent gates.
